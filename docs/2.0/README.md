# OpenXP 2.0

OpenXP 2.0 replaces every part that came from RestedXP (the engine, the 1-20
guides, the data files and textures) with OpenXP's own, so OpenXP can move
from CC BY-NC-SA 4.0 to GPL-3.0. Once it is GPL-3.0 it can use PoleStar's
code and the open forever-db quest database, with credit.

This work lives on the `openxp-2.0` branch. Nothing here is released until
it has been tested in game; 1.3.x fixes keep going to `main`.

## Phases

| Phase | What | State |
| --- | --- | --- |
| 0 | Branch, library licences, guide converter and its test | done |
| 1 | Core engine: guide data loader, step engine, quest state, guide list | done |
| 2 | Card UI, arrow, smart start, terrain, travel and map pins on the new engine | next |
| 3 | 1-20 guides for every race and Skyborne | |
| 4 | Settings, automation, item and target buttons, timers, data from forever-db | |
| 5 | 1.3.x save importer, private test build | |
| 6 | CurseForge beta, then release | |

## Layout

The 1.x addon fills the repository root, mixing game files, guide data,
tools and tests in one place. 2.0 keeps the shipped addon in its own folder,
so a release zip is just that folder and the dev files never ship.

```
OpenXP/                     the 2.0 addon, exactly what goes in AddOns/OpenXP
  OpenXP.toc
  Core/                     no game logic: namespace, events, saved data, player
    Init.lua                OXP.On (game events), OXP.Listen/Send (messages),
                            OXP.Soon (once-per-frame work), OXP.OnLoaded/OnReady
    Util.lua                small helpers
    SavedData.lua           OpenXPDB (account) and OpenXPCharDB (character)
    Player.lua              faction, race, class, level
  Engine/                   guide logic, no UI
    Filters.lua             "only" filters ("Human Paladin/Dwarf Paladin")
    QuestState.lua          quest log, objectives, turned-in quests
    World.lua               zones, flight paths, hearthstone, bag items
    Goals.lua               what each goal kind means and when it is done
    Registry.lua            every guide: checks, keys, lists, #next
    Runner.lua              runs the loaded guide step by step
  Guides/                   guide data, generated by tools/convert_guides.py
    Guides.xml              lists every data file (generated)
    Leveling/Alliance/      21-30.lua, 30-40.lua, ...
    Leveling/Horde/
    Dungeons/               Alliance.lua, Horde.lua
  (phase 2+) UI/, Nav/, Data/, Media/, Libs/, Locales/
tools/                      dev scripts (never shipped)
tests/                      tests (never shipped); tests/lib/fakewow.lua is a
                            headless WoW client the engine runs in
docs/
```

Rules for the new code:

- Every file starts with `local _, OXP = ...`; no globals except the saved
  variables.
- Modules talk through `OXP.<Module>` functions and messages, never by
  reaching into each other's locals.
- `Core/` and `Engine/` never touch frames or textures; the UI only reads the
  engine and listens to its messages. That keeps the engine testable outside
  the game.
- Game API calls stay in the module that owns them (quest log calls only in
  QuestState, zone/taxi/bind calls only in World), so Forever client quirks
  have one place to fix.
- New saved variables (`OpenXPDB`, `OpenXPCharDB`); 2.0 never reads or
  changes the 1.x `OXP*` ones until the phase 5 importer.

The 1.x files stay at the repository root until phase 2 replaces them, and
`tools/package.py` leaves `OpenXP/` out of 1.x release zips. When 2.0 ships,
the AddOns link (or copy) must point at the repository's `OpenXP/` folder,
not the root.

## Engine

A guide is a table of steps; a step is a list of goals, each `{ kind, ... }`.

| Goal | Done when | Blocks the step? |
| --- | --- | --- |
| `accept` | the quest is in the log or turned in | yes |
| `complete` | that objective is done, the quest is complete, or turned in | yes (optional: only while the player has the quest) |
| `turnin` | the quest is turned in | yes (optional: only while the player has the quest) |
| `collect` | `count` of the item in bags | yes |
| `xp` | player level >= `level` | yes |
| `zone` | the player is in that zone or sub-zone | yes |
| `fp` | the flight path is known (taxi map seen, or "New flight path discovered" while the step is shown) | yes |
| `home` | hearthstone set to the town in its name or text (any new bind while shown, if no town given) | yes |
| `text`, `goto`, `area`, `target`, `mob` | hints | no |

The current step is the first unfinished one. A step is finished when none
of its goals is still to do, when the player skipped it, or, for a
`completewith = "next"` step (travel, "kill these on the way"), when the step
after it is finished; both are shown together. Steps already done are passed
over when the guide reaches them. Going back to a step holds it on screen
until the player moves on. Each character's place in every guide is saved,
and a finished guide loads its `#next`.

Guide keys are `<group>/<name>`, plus ` <only>` for guides limited to some
players (the Alliance and Horde versions of a dungeon share a name).
`Registry.Problems()` lists data errors found at load (unknown goal kinds,
filter typos, missing fields, steps with only hints); the tests require it
to be empty.

Messages the UI listens to: `GUIDE_LOADED`, `STEP_CHANGED`, `STEPS_UPDATED`,
`GUIDE_FINISHED`, `NO_GUIDE` (a character with no guide yet: smart start's
cue), plus `QUESTS_CHANGED`, `ZONE_CHANGED`, `BAGS_CHANGED`, `PLAYER_LEVEL`.

### 1.x calls and their 2.0 equivalents (for phase 2)

| 1.x (our files) | 2.0 |
| --- | --- |
| `addon.IsOnQuest(id)` | `OXP.Quests.IsOnQuest(id)` |
| `addon.IsQuestTurnedIn(id)` | `OXP.Quests.IsTurnedIn(id)` |
| `addon.IsQuestComplete(id)` | `OXP.Quests.IsComplete(id)` |
| objective text / counts | `OXP.Quests.GetObjective(id, n)` |
| `addon.currentGuide` | `OXP.Engine.GetGuide()` |
| `addon.GetGuideProgress` | `OXP.Engine.GetProgress(guide)` |
| current / active steps | `OXP.Engine.GetPosition()`, `GetActive()`, `GetSteps()` |
| goal and step state | `OXP.Engine.GoalState(pos, goal)`, `StepState(pos)` |
| load / skip / back | `OXP.Engine.Load(key, step)`, `Next()`, `Back()`, `GoTo(pos)` |
| guide lists | `OXP.Registry.ForPlayer()`, `Groups()`, `Find()`, `Next()` |
| `addon.settings` | `OXP.settings` (account), `OXP.char` (character) |

## Tests

`python3 tests/run_tests.py` runs everything. For 2.0:

- `tests/engine_test.lua`: filters, guide checks, every goal kind, optional
  quests, completewith, going back and skipping, saving and restoring a
  character's place, handing over to `#next`, the UI messages, and the quest
  log read both through the per-quest API and the old leaderboard calls.
- `tests/playthrough_test.lua`: for every race and class of both factions
  (90 characters), plays the whole 21-60 chain and every dungeon guide in the
  headless client, doing what each step says. It fails if any step can't be
  finished that way, the engine stalls or throws, or the guides don't hand
  over in `#next` order to the end of the chain.
- `tests/convert_roundtrip.py`: the converted data says exactly what the 1.x
  guides say, and the generated files are up to date.

## Guide data

The 2.0 engine reads guides as Lua tables, not text. `tools/convert_guides.py`
turns the 1.x guide files in `Guides/openxp/` into `OpenXP/Guides/`; the
format is described at the top of the script. Until the 2.0 engine replaces
the old one, `Guides/openxp/` stays the source: fix a guide there, then run

    python3 tools/convert_guides.py

`tests/convert_roundtrip.py` (part of `tests/run_tests.py`) loads every
converted file in Lua, writes it back out as 1.x guide text and checks it
matches the source line for line, so the 2.0 data always holds exactly the
same route. It also fails when `OpenXP/Guides/` is out of date. The zone
completion and Forever dungeon guides on the `zone-completion` branch convert
the same way:

    python3 tests/convert_roundtrip.py path/to/Completion-Alliance.lua

The 1.x group names (`RestedXP Forever Guide (A)` and `(H)`) become
`OpenXP Leveling (Alliance)` and `(Horde)`; each guide keeps its old group as
`oldGroup` so the save importer can find a player's place.

## Libraries

Every library bundled in `libs/` was checked for whether a GPL-3.0 addon can
ship it (November 2026). The phase 1 engine uses none of them.

| Library | Licence | OK under GPL-3.0? | 2.0 plan |
| --- | --- | --- | --- |
| Ace3 (AceAddon, AceComm, AceConfig, AceConsole, AceDB, AceDBOptions, AceEvent, AceGUI, AceLocale, AceSerializer) and CallbackHandler | Ace3-style BSD ([wowace.com/projects/ace3](https://www.wowace.com/projects/ace3)); forbids redistributing it standalone, which embedding is not | Yes, embedded | Keep the parts 2.0 uses |
| LibStub | Public domain (its file header) | Yes | Keep |
| HereBeDragons | BSD (`X-License` in its .toc; no LICENSE file in its repo) | Yes | Keep for map and minimap pins |
| LibDeflate | zlib (LICENSE.txt also carries the LGPL text) | Yes | Keep if 2.0 still compresses data |
| plc base64 | MIT (its LICENSE) | Yes | Keep if needed |
| LibDBIcon-1.0 | Ace3-style BSD ([CurseForge](https://www.curseforge.com/wow/addons/libdbicon-1-0)) | Yes, but it needs LibDataBroker | Replace with our own minimap button |
| LibCandyBar-3.0 | Ace3-style BSD ([CurseForge](https://www.curseforge.com/wow/addons/libcandybar-3-0)) | Yes | Drop: only the RestedXP timers use it |
| LibDataBroker-1.1 | None stated ([repo](https://github.com/tekkub/libdatabroker-1-1) has no licence) | Unclear | Drop |
| LibUIDropDownMenu | GPLv2 ([CurseForge](https://www.curseforge.com/wow/addons/libuidropdownmenu)) | No, unless it is "v2 or later" | Drop: only the RestedXP settings, talents and tracker use it |
| `libs/compatibility.lua` | RestedXP's file | No | Rewrite the few helpers 2.0 needs |
